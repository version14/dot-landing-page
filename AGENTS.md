### Vite+ Toolchain

This project uses Vite+ — `vite` and `vitest` in `package.json` resolve to `@voidzero-dev/vite-plus-core` and `@voidzero-dev/vite-plus-test` via `pnpm-workspace.yaml` catalog overrides. The CLI is `vp` (not `vite`). All dev/build/test commands must go through `vp` or `pnpm run <script>` (which delegates to `vp`).

Always run `vp install` (not bare `pnpm install`) after pulling to ensure native bindings are set up correctly. `vite-plus` must remain in `devDependencies` — it provides the native `rolldown-binding.darwin-arm64.node` required at runtime.

### Environment Variables

No env vars required for local dev. For server functions or deployment, prefix public vars with `VITE_` (they are inlined at build time). Secret vars (e.g. `DATABASE_URL`) must **not** use the `VITE_` prefix — they are only available in `createServerFn` and server routes.

### Architectural Decisions

- **File-based routing** via `@tanstack/router-plugin` — add routes in `src/routes/`. The plugin auto-generates `routeTree.gen.ts`; never edit that file manually.
- **Server functions** go in `*.server.ts` or `*.functions.ts` files and use `createServerFn` from `@tanstack/react-start`.
- **Loader data** lives in route `loader` options — prefer SWR caching (`staleTime`) over manual refetches.
- **Theme** is stored in `localStorage` under the key `theme` (`light | dark | auto`). The inline `THEME_INIT_SCRIPT` in `__root.tsx` prevents flash-of-unstyled-content.
- **Devtools** are registered on the `TanStackDevtools` component in the root document shell and stripped from production builds via `removeDevtoolsOnBuild`.

### Known Gotchas

- Use `vp dev` / `pnpm dev` — never `vite dev` directly; `vite` has no standalone binary here.
- Do not edit `src/routeTree.gen.ts` — it is auto-generated by the router plugin on dev/build.
- `vite-plus` must stay in `devDependencies` for native rolldown bindings; removing it breaks startup.
- Route files must use `createFileRoute('/<path>')` exactly matching the filename.
- `VITE_` prefixed env vars are public and baked into the client bundle; never put secrets there.
